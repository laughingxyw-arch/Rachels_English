# 单人学习记录同步

本部署只有一份个人学习记录。生产环境 `SINGLE_USER_STUDY=true`，`single_study_profile` 的唯一行指向原恢复码对应的历史账户；真实账户标识只存在数据库和私有备份，不写入代码或 APK。`/api/study` 统一读写这份记录，不要求恢复码、网页、指纹或登录。旧客户端的随机凭据或过期会话也不会再切换到其他账户。

App 保留本机离线累计，使用本机安装 UUID 区分增量；云端同一设备/日期/课程取累计最大值，再按日期与课程汇总，重试不重复计时。下载记录与本机增量分开缓存，卸载重装自动拉取历史。有效学习门槛仍为同一天、同一课程听音累计至少 60 秒。

网络和数据库在 IO 调度器执行；每分钟以及前后台切换、暂停和结束时尝试同步。新安装没有本机增量时只需下载。缓存固定为 `single-study-v1`。Debug/模拟器统计请求指向 `.invalid` 域名，不向生产记录上传测试数据，课程素材仍使用原内容服务。

## 备份与恢复

迁移前完整导出 D1，并在隔离 SQLite 中验证可还原；旧历史学习行不删除。私有导出保存在被 Git 忽略的 `downloads/study-recovery/`。

独立的 Cloudflare 定时任务 `rachels-study-backups` 每天北京时间 03:20 调度，将固定档案快照写入现有 D1 的 `study_backups` 私有表，保留 90 天。任务不启用 workers.dev、预览 URL 或 HTTP 数据接口。每份快照含原始设备/日期/课程累计和 SHA-256；同一天只保存第一次快照，之后修改当前记录不会覆盖当天备份。备份不上传 GitHub，也不进入公开 Git、Release 或 App 接口。

恢复时先另存当前完整数据库，从 `study_backups` 选择正常日期，将该行的 `payload` 和 `sha256` 导出到忽略目录，运行 `node scripts/restore_study_snapshot.mjs <private-snapshot.json> <private-output.sql>`。脚本核对摘要和累计范围、日期、课程、设备、重复项，生成仅替换固定档案学习行的 SQL。核对后用 Wrangler 应用，再检查与快照一致。用户无需保存或输入密钥。

## 退役的绑定流程

App 不再调用通行密钥 API 或处理绑定链接；旧网页只说明现在自动同步。生产绑定 API 返回 410，旧初始化授权撤销，临时下载映射和临时部署清理。旧表保留在迁移前完整备份中，不承担当前同步身份功能。
