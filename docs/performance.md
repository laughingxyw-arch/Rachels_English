# 120Hz 动画与交互验收

用户要求所有动画和交互以小米 15 / Android 16 的 120Hz 体验为目标，避免掉帧。120Hz 的标称帧间隔为 8.33ms；应用侧 CPU、RenderThread 和 GPU 工作应留有余量，不能把 60Hz 的 16.67ms 当作通过标准。

## 真机测量

- 使用正式签名的 Release 或与 Release 优化设置一致的性能构建，在小米 15 上测量。记录版本、提交、Android 版本、实际刷新率、温度与省电状态。
- 确认操作期间实际显示刷新率为 120Hz。屏幕支持 120Hz 或平均 FPS 接近 120 都不能替代逐帧结果。
- 使用 Perfetto FrameTimeline 检查帧 deadline 和 jank，并关联主线程、RenderThread、GPU、布局及垃圾回收；Macrobenchmark 的 FrameTimingMetric 可记录 CPU 帧耗时和 deadline overrun。
- 分场景报告样本数、P50 / P95 / P99、最大耗时、deadline 超时帧和卡顿率，目标是测试操作中没有应用引起的超时/掉帧。区分系统或 SurfaceFlinger 卡顿，不静默删除异常样本。
- 冷启动、首次解码、缓存命中和持续操作分别测量；每个常用操作至少重复 20 次，再检查持续操作后的热状态。声明覆盖范围，不能用一次通过承诺所有设备和系统状态下零掉帧。

## 必测操作

- 首页快速滚动、点击课程、阅读页返回；分别覆盖封面可见与已滚出屏幕。
- 返回手势缓慢拖动、快速松手、中途取消，以及恢复过程中再次拖动。
- 播放器弹出与收回、暂停/继续、连续切句、Drill 模式和次数切换。
- 设置面板打开、拖动关闭、展开复读次数及显示辅助。
- 播放中滚动、文字跟读轨迹、播放器背景模糊和轻提示同时出现。
- 切换减少动态效果、减少透明效果、高对比度和省电模式，检查响应与视觉回退。

## 实现与回归要求

- 网络、音频文件准备、封面解码和校验不阻塞主线程；缓存解码结果。
- 高频动画状态尽量在布局或绘制阶段读取，避免让每次音频进度更新触发整页重组；缓存文字测量和不变绘制资源。
- 检查共享转场的每帧重测量成本，尤其是 animated placeholder 对列表及相邻课程布局的影响。
- 背景模糊只过滤可见浮动表面，复用图形层和滤镜；检查来源图层的重复录制、过度绘制及面板过滤面积。
- 优先优化实测热点；必要时简化光影和模糊复杂度，保持可读性、空间连续性和手势响应。
- 不通过缩短动画、隐藏功能、强制忽略系统省电或减少动态效果设置来掩盖性能问题。

## 当前验证状态

2.1.6 已通过云端 Release 编译、25 项单元测试和 10 项原生模拟器测试。新增真实坐标触摸回归在返回落地的首个可见帧点击课程，覆盖按钮/侧滑返回后立即进入同一课程及另一课程；加载竞争回归覆盖新请求仍在等待和同一课程新实例已完成两种情况。目标页面触摸层级只随导航目标改变，不增加逐帧计算。新增回归逐帧检查 Tower Bridge 共享标题保持一行、进入与返回途中时长标签具有中间透明度，并验证真实音频切段后总任务进度保留、单句与无限循环不暴露进度条。任务时间轴按音频与留白预计算，进度查询为 O(1)；标签透明度和播放器填充动画在图形层/绘制阶段读取，不增加模糊过滤范围。

上一版返回交接前后可见容器高度差不超过 1px、设置背景缩放、手势取消/重新拖动与材质像素回归继续通过。数学测试保留 60Hz / 120Hz 的弹簧末帧采样。尚未获得小米 15 的真机帧时间记录，**120Hz 稳定性未验证**；数学与云端模拟器检查不作为真机性能验收。
